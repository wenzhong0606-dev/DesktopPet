# M4-B — 本地长期记忆与自动形成

M4-A Windows 本机验收仍按用户决定延后。M4-B1 基线 CI 已通过；本轮实现 M4-B1 修订与 M4-B2 的首个本地自动提取增量，新增 CI 与 Windows 本机验收另行记录。

## 当前实现

- 每个 Companion ID 独立存储记忆。兼容升级原有 SQLite 表，保留旧数据；旧条目标记为手动确认。
- 不设固定记忆总数上限，管理界面每页 30 条，查询最多 100 条/页，使用按角色和更新时间的数据库索引。单条主题 1–40 字符、内容 1–200 字符。
- 检索由数据库完成，只返回最多 4 条相关结果；检索范围不再受前 200 条限制。按主题或类别及少量饮食/音乐意图关键词匹配，暂非语义向量检索。后续增加上下文预算与更强相关性。
- 独立的自动形成开关和云端检索开关均按角色保存、默认关闭。开启自动形成后，在新用户消息成功持久化时本地提取，不要求逐条确认，无额外 AI 请求，不扫描旧聊天。
- 当前自动提取采用有限白名单与明确第一人称陈述语法，仅覆盖普通饮食、音乐、兴趣偏好（支持部分省略主语的并列陈述）。问题、假设、第三人称、复杂或超出白名单的内容拒绝提取。白名单并非通用敏感数据检测器；不得把其描述为完整自然语言理解。
- 自动记录从实际持久化的同角色 user 消息取得，保存分类、来源、来源消息 ID 和 explicit_statement 证据等级；不使用 assistant 生成的内容作为事实。来源 ID 仅供定位，删除历史后来源消息可能不可用，不复制完整消息。
- 同主题自动提取不覆盖任何已有记录；重复不新增，冲突由用户手动纠正，当前对话陈述优先于旧记忆。完整冲突策略留给 M4-B3。
- 管理窗口支持分页、查看、补充、同主题修改、删除、清空及来源标记。手动修改将记录标记为用户确认。手动管理不是形成普通记忆的必要步骤。
- 聊天历史与记忆分别管理；删除记忆不撤回过去云端请求或包含该事实的历史回复。关闭自动形成不清空已有记忆；关闭检索不清除历史。自动形成仅本机处理；只有单独开启检索，相关记忆才加入 Qwen 请求。普通聊天仍按现有协议发送近期上下文。
- 数据库未额外加密，请勿保存密码、凭据等敏感信息。记忆异常不阻断普通聊天；无 Qwen Key 时可管理记忆并查询本地时间。

## 后续阶段

- M4-B2 继续扩展可靠的自然语言提取与分类，建立准确性评估。
- M4-B3（P1）：重复合并、冲突更新、有效期/归档、语义检索与动态上下文预算。
- M4-B4（P2）：共同经历与关系记忆。
- M4-B5（P2）：渐进人格成长，可重置、可回滚，不改写基础人格。

## 回归验收

验证超过 200 条仍能写入及检索、分页无重复遗漏、旧 schema 迁移、两类授权独立、角色隔离、仅用户来源、拒绝不适合提取的消息、重复/冲突不覆盖、管理与历史分离。Windows GUI 与真实 Qwen 尚待本机验收。
