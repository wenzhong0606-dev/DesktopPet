- 文档状态：已确认的产品方向与开发基线
- 基线日期：2026-11-27
- 当前仓库：`wenzhong0606-dev/DesktopPet`

- 当前运行平台：Windows 10/11 x64
- 当前技术基线：.NET 10 / WPF

## 1. 一页产品定义

### 1.1 产品定位

AI Desktop Companion 是一个运行在 Windows 桌面上的可定制 AI 桌面伙伴平台。用户可以选择平台角色，也可以逐步导入自己拥有合法使用权的角色模型；伙伴通过外观、动作、表情、声音和 AI 对话与用户互动。

比熊是第一个示范角色，不是平台唯一角色，也不限制未来角色类型。

### 1.2 产品愿景

让用户把自己喜欢的角色带到桌面上，使其能够持续展示、对用户操作作出反应、通过文字或语音交流，并在角色能力允许的范围内表现出符合自身物种或形态的行为。

### 1.3 核心产品原则

1. **每阶段可运行**：每个里程碑必须交付可编译、可启动、可体验、可验收的独立版本。
2. **小步交付**：只实现当前阶段验证用户价值所必需的能力，不提前建设大型平台。
3. **保护已验收成果**：新增功能不得破坏现有图片桌宠展示和既有交互。
4. **角色开放**：产品不限定比熊；角色类型、外观和来源可以逐步扩展。
5. **能力诚实**：模型没有骨骼或动画时，只承诺静态展示；不声称任意模型可自动获得完整动作。
6. **角色能力驱动行为**：AI 只能选择角色已声明并经程序允许的动作，不直接执行任意代码。
7. **隐私优先**：基础桌宠离线可用；云端 AI、麦克风和语音功能均由用户主动启用。
8. **渐进式架构**：提前约定稳定的数据边界和标识，不提前实现尚未需要的通用引擎。

## 2. 目标用户与主要需求

- 希望在 Windows 桌面上拥有轻量陪伴角色的用户。
- 喜欢不同动物、虚拟人物或原创角色的用户。
- 希望上传自己制作、购买或获授权模型的创作者。
- 希望与桌面伙伴进行文字、语音和动作互动的用户。

主要任务（Jobs to be Done）：

1. 在桌面上显示并管理自己喜欢的角色。
2. 轻松移动、隐藏、恢复和配置桌宠。
3. 让角色对点击、拖动、语音或文字作出恰当反应。
4. 在角色支持的范围内调用专属动作。
5. 导入个人模型并逐步配置角色名称、人格、声音和动作能力。

## 3. 角色体系与数据边界

### 3.1 角色类型

平台未来可以支持但不限于：

- 四足犬类：比熊、边牧、金毛、柴犬等。
- 猫科及其他常见动物：猫、兔子、狐狸等。
- 爬行动物：蜥蜴、变色龙、乌龟等。
- 人形角色：成年女性、成年男性、动漫风格人物等。
- 其他原创生物或用户自定义角色。

以上是产品方向，不代表首版全部实现。

### 3.2 角色的四个独立维度

1. **外观（Appearance）**：图片或 3D 模型、材质、服装和配饰。
2. **骨骼与动作能力（Rig & Capabilities）**：骨骼类型、可用动作、表情和动作资源。
3. **人格与声音（Persona & Voice）**：名称、性格、语气、声音配置。
4. **AI 交互（AI Interaction）**：意图理解、对话、记忆和行为决策。

这四个维度应保持解耦。模型决定外观；Rig 和动作能力决定可执行的运动；人格决定表达风格；AI 负责理解用户并提出受约束的行为建议。

### 3.3 角色能力约束

- 四足动物、人形、爬行动物使用不同的 Rig Profile。
- 不同角色可以声明不同动作集合。
- AI 只能调用角色清单中存在、运行时已加载且通过校验的动作。
- 不支持的动作应转为自然语言回应或替代动作。
- 不允许把简单节点旋转冒充复杂的打滚、握手、走路等真实动作。

### 3.4 角色包的渐进式约定

未来角色包可逐步包含：

- 稳定的角色 ID、显示名称、版本。
- 角色类型和物种/形态标识。
- 资源入口及授权/来源声明。
- 展示类型（当前图片；未来 3D）。
- 可选 Rig Profile。
- 可选动作和表情能力清单。
- 可选人格、声音和用户偏好配置。

MVP 阶段不实现完整角色包市场或复杂插件系统。先采用简单、可版本化的本地 JSON 清单。

## 5. 渐进式 MVP 路线图

### M0 — 图片桌宠展示（当前基线）

**目标**：保留已经完成的图片桌宠展示。

**状态**：用户确认图片桌宠展示已完成；仓库已有图片加载实现和 PNG 文件。

不因平台方向升级而重做 M0。

### M1 — 可日常使用的图片桌宠 V1.0

**目标**：补齐当前图片桌宠作为日常 Windows 应用所需的最小体验。

优先核对并补齐：

- 明确的托盘显示/隐藏入口。
- 简洁的设置窗口：置顶、雪花、装饰灯、音乐等已有选项。
- 设置变更即时生效并持久化。
- 明确的退出与资源释放。
- 基础异常记录和可诊断的设置读写失败。
- 修正 README、资产清单和运行说明中的过期状态。
- 增加关键设置和状态行为测试。

不在 M1 加入多角色、AI、语音或 3D。

**交付物**：可独立运行、离线可用的图片桌宠 V1.0。

### M2 — 多图片角色管理

**目标**：让用户不再被固定的比熊图片绑定。

范围：

- 本地角色列表。
- 导入常见图片资源。
- 角色名称和简单元数据。
- 切换、删除和恢复默认角色。
- 每个角色的基础配置独立保存。

不在 M2 实现 3D 导入、动作重定向或角色商店。

**交付物**：可运行的多图片角色桌宠。

### M3 — 轻量行为系统

**目标**：使图片角色能够依据用户操作表现不同状态。

范围：

- 有限的待机、点击、欢迎、开心、困倦等状态。
- 根据角色资源清单选择已有图片/帧序列。
- 规则驱动的动作选择和状态回退。
- 基础随机行为及频率控制。

不要求此阶段接入 AI。

**交付物**：具有可感知互动反馈的图片桌宠。

### M4 — AI 文字交互

**目标**：用户可以通过文字与角色交流。

范围：

- 文字输入和回答展示。
- 可替换的 AI Provider 接口。
- 意图识别和受约束的行为指令。
- 角色能力清单校验。
- 网络失败、额度不足和服务不可用时的降级。
- 基础会话管理。

云端 AI 必须由用户主动配置/启用；无 AI 时桌宠仍可正常运行。

**交付物**：可文字交流并触发有限角色行为的桌宠。

### M5 — AI 语音交互

**目标**：让用户通过语音与角色交流。

范围：

- 用户主动触发的按住说话（Push-to-talk）。
- ASR 语音识别。
- TTS 语音合成。
- 文字、语音、角色动作协调。
- 麦克风权限、音量、错误和费用提示。

默认不启用常驻监听或自动唤醒。

**交付物**：支持主动语音输入和语音回答的桌宠。

### M6 — 单角色 3D 技术验证

**目标**：以一个正式角色验证 Windows WPF 桌面环境中的实时 3D 可行性。

范围：

- 加载一个真实 GLB/glTF 模型。
- 实时旋转、缩放和渲染。
- 一个待机动作和一至两个互动动作（模型资源具备时）。
- 透明窗口、鼠标交互和资源释放验证。
- 在目标 AMD/Intel 集成显卡设备上测量性能。

候选方案可包括 WebView2 + Babylon.js，但必须通过小型技术验证后再决定，不提前承诺最终 3D 引擎。

**交付物**：可运行的单角色 3D 桌宠技术样机。

### M7 — 用户 3D 模型导入

**目标**：让用户把自己合法拥有或获准使用的模型放到桌面。

首版优先支持 GLB/glTF 静态模型：

- 文件导入和本地存储。
- 文件大小、格式、网格、材质和纹理检查。
- 模型预览、缩放和位置调整。
- 角色名称及来源/授权声明。
- 清楚区分静态展示、内嵌动画和可绑定 Rig 的模型。

VRM、FBX、OBJ 等格式按需求逐步增加；必要时通过 Blender 转换。没有 Rig 的模型不承诺自动获得完整动画。

**交付物**：用户可导入并展示自己的静态 3D 角色。

### M8 — 角色 Rig 与动作能力扩展

**目标**：逐步支持不同身体结构的动作。

按实际角色需求建立独立 Rig Profile，例如：

- Quadruped Dog
- Quadruped Cat
- Reptile
- Humanoid

先为一个目标 Rig 完成可验证的动作集，再评估动画重定向和自动绑定。不同物种不得强行共用同一套动作。

**交付物**：至少一个经过验证的 Rig Profile 和角色动作集；后续类型逐步增加。

### M9 — 开放角色生态（远期，暂不排期）

可能范围：

- 用户创作与分享角色。
- 角色动作包。
- 官方/社区角色库。
- AI 辅助角色配置。
- 服装、配饰和人格模板。

只有在本地导入和角色运行体验成熟后，才评估云端社区或商店。

## 6. 渐进式技术架构

当前阶段保留 .NET 10 WPF，不进行技术栈重写。

逐步演进的模块边界：

1. **Desktop Shell**：WPF 窗口、托盘、桌面交互、设置和生命周期。
2. **Avatar Presentation**：当前图片展示；未来通过独立适配层增加 3D。
3. **Avatar Manifest**：角色稳定 ID、资源、版本和能力声明。
4. **Behavior / Action Registry**：可用行为及其运行时校验。
5. **AI Provider Adapter**：后续接入可替换 AI 服务。
6. **Voice Adapter**：后续接入 ASR/TTS。
7. **Local Storage**：本地设置、角色元数据和用户可管理的记忆。

### 现在需要保持稳定的约定

- 稳定的角色 ID。
- 角色清单的版本字段。
- 展示资源与行为能力分离。
- AI 指令必须经过白名单和角色能力校验。
- 本地数据路径和隐私边界明确。

### 现在不建设的系统

- 通用跨物种骨骼/动作重定向引擎。
- 自动 Rig 服务。
- 角色市场和交易系统。
- 云端账号及同步系统。
- 常驻麦克风监听。
- 多智能体系统。
- 跨平台客户端。
- 复杂插件或微服务平台。

## 7. 隐私、安全与授权

- 基础图片桌宠必须在断网时可运行。
- 不默认上传本地模型或用户文件。
- AI 云端调用应告知用户会发送哪些文本或数据。
- 麦克风仅在用户主动授权和启动语音功能后使用。
- 用户应能查看、关闭和删除本地保存的偏好/记忆。
- 用户导入模型时应确认拥有合法使用权。
- 分享或分发模型时必须检查原作者授权、二次修改和再分发限制。
- AI 只能发出应用定义的动作意图，不能执行任意系统命令、脚本或文件操作。

## 8. 性能与兼容性原则

- 当前目标是 Windows 10/11 x64。
- 当前用户设备为 AMD/Intel 图形环境、32GB 系统内存；不能假设存在 NVIDIA CUDA。
- 图片版本应保持轻量、低资源占用。
- 3D 技术验证必须在目标设备上实测帧率、内存和窗口透明效果。
- 3D 引擎选择以实测结果为准，不以理论功能清单为准。

## 9. 版本和验收规则

版本建议：

- M0：当前图片展示基线。
- M1：图片桌宠日常可用版。
- M2：多图片角色版。
- M3：规则行为版。
- M4：AI 文字版。
- M5：AI 语音版。
- M6：3D 技术样机。
- M7：用户 3D 导入版。
- M8：Rig/动作扩展版。

每个里程碑完成必须满足：

1. 代码可编译。
2. 程序可启动。
3. 核心场景通过冒烟测试。
4. 之前已验收的功能没有回归。
5. 文档、版本记录和已知问题同步更新。
6. 对无法在开发环境验证的 Windows 行为，明确交由用户本机验收，不得虚报通过。

任何阶段未达到退出标准，都先修复当前阶段，不进入下一阶段。
