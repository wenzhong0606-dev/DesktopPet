# 本机环境感知与主动关怀

状态：M4-A 增量已实现，待 Windows 本机交互验收。

## 产品原则

桌宠不要求用户填写固定起床/睡觉时间，也不通过持续追踪精确位置来推断生活。优先使用本机可得、低敏感度的信息；外部位置和天气服务必须显式启用。规则引擎判断事实和触发时机，宠物人格只影响措辞。

## 能力组成

### 本机时间

- \`SystemClockService\` 读取 Windows 本地日期时间、星期、时区 ID 和 UTC 偏移。
- \`LocalTimeQueryHandler\` 对明确的“现在几点/当前时间/今天几号/今天星期几”等问题直接本地回答，不调用 Qwen。
- 其他 Qwen 对话的 system context 也会附带当前本机时间；时间信息在请求时生成，不缓存为静态文本。

### 活动节奏

- \`WindowsActivityMonitor\` 通过 \`GetLastInputInfo\` 读取最近一次键盘或鼠标输入距今的空闲时长。
- 不读取键盘内容、鼠标坐标、窗口标题、前台应用、网页或文件，不安装输入钩子。
- 空闲达到 5 分钟即结束连续活跃段；连续活跃达到 60 分钟产生一次温和休息建议；下一次提醒至少间隔 90 分钟。
- 用户可以在设置中关闭本地活动感知。
- 当前版本不设定或推断睡觉时间，也不保存跨日活动画像。它是基于当前连续使用时段的第一版规则，不会把深夜使用电脑等同于不健康作息。

### 位置与 VPN/代理识别

位置只用于天气，不用于识别用户身份。

优先级：
1. 用户手动设置的城市（最高优先级）。
2. 用户明确启用后，使用 IPLogs 对当前网络出口进行城市估算和匿名网络检测。
3. 检测到 VPN/代理/中继/不可信网络时，不采用该出口城市；若有上一次可信城市则继续使用，否则要求用户手动设置。

本地安全检查：
- Windows 系统代理若会影响 IPLogs 请求，则跳过自动 IP 定位。
- 检查已启用的 Tunnel 网络接口或名称包含常见 VPN/隧道标记的网络接口；发现疑似隧道时跳过自动 IP 定位。
- 本地检查是保守启发式，可能误判企业网络或特殊适配器。

IPLogs 远端检查：
- 仅在用户开启天气提醒且勾选自动 IP 城市定位后调用 \`POST https://iplogs.com/v1/check\`，发送空 JSON 对象并省略 \`ip\` 字段，以检查当前请求来源出口。
- 仅当 verdict 为 \`clean\`、score 小于 0.30、\`is_vpn\` 明确为 false，且响应中任何 proxy/Tor/relay/hosting/satellite 标记均未为 true 时接受其城市/国家；随后由 Open-Meteo Geocoding 将该城市解析为天气坐标。IPLogs 不提供可依赖的城市经纬度字段。
- 任何可疑、缺失或不完整结果均 fail closed：不采用出口位置。
- 不尝试通过 VPN 隧道反查原始公网 IP。无法可靠地从 VPN 出口推断真实位置。

数据处理：
- 设置中默认关闭自动 IP 定位。启用前明确告知当前公网 IP 会发送给 IPLogs。
- IPLogs 的公开 FAQ 声明访问日志保留 30 天；其 API 条款说明地理位置字段来源于 DB-IP，采用 CC BY 4.0。参考：[IPLogs API 文档](https://iplogs.com/docs)、[IPLogs FAQ](https://iplogs.com/faq)、[IPLogs 条款](https://iplogs.com/terms)。
- 本机只保存城市、国家、城市级经纬度、时区/来源和更新时间；不保存原始公网 IP。
- IP 城市是近似位置，不是 GPS 或家庭地址。当前版本没有接入 Windows 精确位置 API。

### 天气与主动关怀

- 手动城市和经 IPLogs 验证可信的城市/国家都通过 Open-Meteo Geocoding API 解析为城市级坐标。
- 天气预报由 Open-Meteo Forecast API 提供逐小时温度、体感温度和降水概率。
- 只有用户开启天气关怀后才会发起城市解析/天气请求；城市坐标和网络请求会被 Open-Meteo 接收。
- 规则阈值：
  - 添衣：当前体感温度不高于 8°C；或未来 6 小时最低温不高于 8°C；或未来 6 小时降温至少 6°C 且最低温不高于 14°C。
  - 带伞：未来 3 小时内任一小时降水概率达到 70%。
  - 防暑：当前体感温度达到 32°C，或未来 6 小时体感温度达到 35°C。
- 每类天气提醒分别持久化 6 小时冷却时间；天气每小时刷新。数据过期、字段缺失或服务不可用时不生成提醒。
- Open-Meteo 的免费 API 仅供非商业用途，天气数据采用 CC BY 4.0 并要求署名。当前集成面向个人/非商业使用；商业发行前必须改用获得商业许可的服务。天气提醒附带 Open-Meteo、DB-IP/GeoNames 和 CC BY 4.0 来源链接。参考：[Open-Meteo Geocoding](https://open-meteo.com/en/docs/geocoding-api)、[Open-Meteo Forecast](https://open-meteo.com/en/docs)、[Open-Meteo 条款](https://open-meteo.com/en/terms)。

## 设置默认值

| 设置 | 默认值 | 说明 |
|---|---|---|
| 本地活动节奏感知 | 开启 | 仅本机空闲时长 |
| IP 自动估算城市 | 关闭 | 需要明确授权 |
| 天气关怀提醒 | 关闭 | 需要关注城市 |
| 手动关注城市 | 空 | 如填写则优先于 IP 城市 |

天气提醒开启但未设置城市、也未授权 IP 定位时，应用会提示补充城市，不会自行定位。

## 验收清单

- 当前时间、日期和星期可在未配置 Qwen API Key 时正常回答。
- “你觉得我几点睡觉比较好”等建议问题不会被误判为时间查询。
- 连续活跃 60 分钟触发休息建议；空闲 5 分钟后重新计时；90 分钟冷却有效。
- IP 自动定位默认关闭；开启后只有可信出口才被采用。
- VPN/代理/中继/数据中心/卫星出口不作为用户城市；有缓存时沿用上次可信城市。
- 手动城市覆盖 IP 定位；城市输入无结果时不产生天气提醒。
- 天气数据使用目标城市时区解释；过期/缺失数据不触发提醒。
- 同类天气提醒冷却跨应用重启仍有效。
- 关闭天气关怀后不再请求 IPLogs、地理编码或天气服务。
